MODULE 01

Terminal, Git & GitHub

Getting comfortable with folders, version control and keeping project work organised.

P1

Project folder and terminal navigation

Create a project folder and move around it using basic terminal commands.

mkdir my-portfolio
cd my-portfolio
mkdir css images
touch index.html
pwd
ls

What I practised: creating folders, changing directories and checking the current location.

P2

Portfolio repo with an initial commit

Start Git in the project, add the files and save the first version.

git init
git add .
git commit -m "Create portfolio starter"
git branch -M main
git remote add origin YOUR_REPO_URL
git push -u origin main

Replace YOUR_REPO_URL with the URL of your own GitHub repository.

P3

Feature-branch Git workflow

Work on a separate branch so a change can be developed without directly editing the main branch.

git switch -c feature/about-section
# make and save your changes
git add .
git commit -m "Add about section"
git push -u origin feature/about-section

After checking the branch on GitHub, it can be merged into main.

P4

GitHub README and version tags

Document what the project does and mark a version that can be referred to later.

git tag -a v1.0 -m "First portfolio version"
git push origin v1.0

A README explains the project. A tag gives a particular commit a version label.

P6

Full portfolio page structure in semantic HTML

Organise a portfolio into a header, navigation, main content sections and footer.

<header>
  <nav aria-label="Main navigation">...</nav>
</header>
<main>
  <section id="about">...</section>
  <section id="projects">...</section>
  <section id="contact">...</section>
</main>
<footer>...</footer>

The sections have IDs so the navigation links can jump to them.

P7

Design tokens and typography system in CSS

Store reusable colours, spacing and font choices as CSS custom properties.

:root {
  --ink: #202b36;
  --paper: #f5f3ee;
  --accent: #d46b4e;
  --space: 1rem;
  --font-body: Arial, sans-serif;
}
body {
  color: var(--ink);
  background: var(--paper);
  font-family: var(--font-body);
}

Changing a token updates every place where that variable is used.

P13

Choosing between Flexbox and Grid for a shared layout

Flexbox is usually best for arranging items in one direction. Grid is useful when rows and columns need to work together.

Flexbox

Navigation links, toolbars and aligned buttons.

Grid

News pages, dashboards and project galleries.

Both can be combined. The choice depends on how the content needs to be arranged.
